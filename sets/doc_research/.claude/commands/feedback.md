Show `doc_research/FEEDBACK.md`, and add an entry if $ARGUMENTS describes a problem.

Use the format at the top of the file: what was being attempted, what went wrong, the researcher's
words verbatim, what you did about it, whether it got resolved, and **which shipped file or rule is
implicated** — that last field is what makes it useful upstream.

Append; never rewrite an existing entry.

If the question is what the file is for: it collects the things that did not work so the
instructions can be fixed upstream rather than worked around forever. It stays on this machine
until it is sent back to whoever set the notebook up, and anything in it can be deleted first.
