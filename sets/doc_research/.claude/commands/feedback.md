Show `FEEDBACK.md`, and add an entry if $ARGUMENTS describes a problem.

Use the format at the top of the file: what she was doing, what went wrong, her words verbatim,
what you did about it, whether it got resolved, and **which shipped file or rule is implicated** —
that last field is what makes it useful to us.

Append; never rewrite an existing entry.

If she is asking what the file is for: it collects the things that did not work so the
instructions can be fixed upstream rather than worked around forever. It stays on her machine
until she sends it to Gabriel, and she can delete anything in it first.
